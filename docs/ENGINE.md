# ミッドナイトライン ― エンジン仕様書

`game/midnightline.html` の実装から書き起こしたリバースエンジニアリング仕様。
本書は **実装が現にどう動くか** を記述する。設計書（`docs/design.md`）との差分は
`docs/GAP.md` を参照。

- 対象実装: 単一HTML版（バニラJS・ビルド不要・`file://` 直開き可）
- 分割後の対応: 状態とロジック = `src/core.js` ／ 描画と入出力 = `src/engine.js`

---

## 1. 全体構造

単一HTMLは 2 つの独立した `<script>` から成る。

| ブロック | 内容 | 分割後 |
|---|---|---|
| データ部 | `STILLS` / `ENDINGS` / `SCENARIO` | `src/data/*.js` + `src/scenario/*.js` |
| エンジン部 | 状態・実行系・描画・音響・パネル | `src/core.js` + `src/engine.js` |

シナリオは章ごとの **ノード配列** で、`SCENARIO[章ID]` に格納される。

| 章ID | 章名 | ノード数 | ラベル数 |
|---|---|---:|---:|
| `pro` | 序章 もしもし、きこえますか | 106 | 16 |
| `ch1` | 第一章 うたたね編 | 204 | 29 |
| `ch2` | 第二章 ともしび編 | 160 | 20 |
| `ch3` | 第三章 かがみめ編 | 151 | 19 |
| `ch4` | 第四章 よふかし編 | 128 | 14 |
| `ch5` | 第五章 ほむら編 | 208 | 27 |
| `fin` | 終章 あさやけ編 | 280 | 48 |
| | 合計 | **1237** | **173** |

## 2. 実行モデル

```
loadChapter(id) → script = SCENARIO[id]
                  labels = { ラベル名: 配列index }   ← n: を持つノードから構築
                  pc = 0
step()          → if (running) return          // タイプライタ表示中は無視
                  exec(script[pc++])
```

- **`pc`（プログラムカウンタ）は単純な配列インデックス**。ラベルは配列位置への別名にすぎず、
  ジャンプしなければ次の要素へ素通しで落ちていく（フォールスルー）。
  つまり `n:` ラベルは「ブロックの終わり」を意味しない。直前のノードから
  そのまま流れ込むことが正常な制御フローとして多用されている。
- `exec()` は **表示系ノードで `running = true` にして復帰**する。ユーザーが画面を
  タップ／スペースキーを押すと `advance()` → `step()` で再開する。
- 表示系以外のノードは処理後に **末尾で `step()` を自己再帰呼び出し**して連続実行される。

### 実行の中断点（ここでユーザー入力を待つ）

| 種別 | ノード | 再開方法 |
|---|---|---|
| テキスト表示 | `say` / `me` / `nar` | タップ or スペース（`advance`）|
| システム表示 | `sys` | 同上（タイプライタなし・即時全文表示）|
| 選択肢 | `ch` | 選択肢クリック（`pick`）または制限時間切れ |
| スチル | `still` | スチル画面クリック（コールバックで `step()`）|
| 章タイトルカード | `card` | 2.4秒後に自動（タイマーで `step()`）|
| ウェイト | `wait` | 指定ミリ秒後に自動 ※シナリオ未使用 |

## 3. ノード種別

ノードは **プレーンオブジェクト1個 = 1ノード**。キーの有無で種別が決まる。
複数キーを1ノードに同居させられる（下記「評価順」参照）。

### 3-1. 表示系（実行を中断する）

| キー | 型 | 意味 |
|---|---|---|
| `say` | string | セリフ。話者は `c` で指定。タイプライタ表示。**時刻+1分** |
| `c` | string | 話者キャラID（`CHARS` のキー）。未知IDは `UNK` にフォールバック |
| `nm` | string | 名前の上書き表示（`???` / `ムニ(15)` など、正体を伏せる用）|
| `slow` | 1 | タイプ速度を 22ms → 46ms に落とす（重要台詞の演出）|
| `w` | 1 | 囁きスタイル（`.tx.wsp`）※**シナリオ未使用** |
| `se` | string | 効果音キー（`SE` 表を引く）※**シナリオ未使用** |
| `me` | string | 主人公の発話。**時刻+1分** ※**シナリオ未使用**（選択肢の `line` で代替）|
| `nar` | string | 地の文。タイプライタ表示。**時刻は進まない** |
| `sys` | string | システム表示（水色の枠線付き）。HTML可（`<br>` 使用）。タイプライタなし |

### 3-2. 演出系（即時実行し、そのまま次のノードへ）

| キー | 型 | 意味 |
|---|---|---|
| `call` | `{who, c, num}` | 通話開始。ヘッダの相手表示を更新し、`callStart` に現在時刻を記録 |
| `hang` | string | 通話終了。文字列は切電理由（通話履歴に残る）|
| `hangKind` | `'normal'`/`'cut'`/`'silent'` | 切電音の種類。`silent`（無音）が消失フラグの署名音 |
| `ring` | `'normal'`/`'old'`/`'broken'` | 着信音。`old`=十年前の黒電話ベル、`broken`=文字化け着信 |
| `noise` | 0〜3 | ノイズレベル（境界接近度）。画面効果とヘッダ表記が連動 |
| `fx` | `'shake'`/`'flash'` | 画面揺れ／白フラッシュ |
| `amb` | 0〜6 | 環境ドローン音の章レベル ※**シナリオ未使用**（`card[3]` で代替）|
| `clock` | `'HH:MM'` | 時刻を直接セット |
| `day` | number | 日付をセット。**時刻は 22:00 にリセットされる** |
| `still` | string | スチル解放＋全画面表示。閉じると `step()` で再開（**中断点**）|
| `card` | `[ラベル, 題名, 日付, ambLv]` | 章タイトルカード（**中断点**）。第4要素は環境音レベル |
| `chapTitle` | string | ヘッダに出す章名を更新（`card` とは別）|
| `wait` | number(ms) | 指定時間待って再開 ※**シナリオ未使用** |
| `sec` | number(秒) | 次の選択肢ノードの制限時間。§4 参照 |

**ノイズレベルの表示対応**

| lv | ヘッダ表記 | 画面 |
|---|---|---|
| 0 | 回線良好 | 素 |
| 1 | 微弱な雑音 | 粒子強 |
| 2 | 二重音声を検知 | 粒子＋周辺減光、着信ランプ点灯 |
| 3 | 境界接近 — 回線不安定 | さらに強化＋色相アニメーション |

### 3-3. データ系（状態を書き換える。即時・連続実行）

| キー | 型 | 意味 |
|---|---|---|
| `set` | `{FLAG: value}` | フラグを代入セット |
| `inc` | `{FLAG: n}` | フラグを **カウンタとして加算**（`MUN_CUT_XX` 専用の使い方）|
| `par` | `{c, trust?, doubt?, fear?, stress?}` | パラメータ増減（選択肢外での変動用）|
| `meet` | string | キャラと初遭遇。`MET_<ID>` フラグを立て、右ペインに表示開始 |
| `known` | string[] | `meet` と同ノードで、判明情報の**初期値**をセット |
| `know` | `[キャラID, 情報文]` | プロフィールに情報を1件追記（重複は無視）|
| `life` | `[キャラID, 生死]` | 生死を `生存`/`危篤`/`死亡`/`消失` に変更 |
| `memo` | `[題名, 本文]` | 相談メモに追加＋トースト通知 |
| `evd` | `[題名, 本文]` | 証拠一覧に追加＋トースト通知 |
| `tl` | `[日付, 内容]` | 事件年表に**追記** |
| `tlfix` | `[日付, 内容]` | 事件年表の **index 1（＝空白行）を上書き**。年表の空白を埋める専用 |
| `rel` | `[A, 関係, B, dot?]` | 人物相関図に線を追加。第4要素が真なら点線（周回限定の隠し線）|
| `vm` | `[題名, 本文]` | 留守番電話に追加（未再生バッジ付き）|
| `rec` | `{id, ti, tx, hid, flag}` | 録音を追加。`hid` = 減速/逆再生で判明する裏内容、`flag` = 発見時に立つフラグ |
| `toastx` | 1 | ムニへの刷り込み到達数（n/3）をトースト表示 |

### 3-4. 制御系

| キー | 型 | 意味 |
|---|---|---|
| `ch` | option[] | 選択肢を表示（**中断点**）。§4 参照 |
| `go` | ラベル名 | 無条件ジャンプ |
| `if` | 条件式 | 条件成立で `go2 ?? then` へ、不成立で `els` へジャンプ。`els` 省略時は素通し |
| `chap` | 章ID | 章を切り替え、テキスト欄をクリアして先頭から実行。自動セーブ |
| `end` | `'check'` or END名 | ゲーム終了。`'check'` なら `judge()` で判定、それ以外は直接そのENDへ |
| `clear` | 1 | テキスト欄をクリア ※**シナリオ未使用** |

### 3-5. 評価順の重要な注意

`exec()` は 3-1 → 3-2 → 3-3 → 3-4 の順に **同一ノード内で上から素直に評価する**。
そのため次の性質がある。

1. **表示系（`say`/`me`/`nar`/`sys`）は即 `return`** する。
   同じノードに `set` などを同居させても **実行されない**。フラグ操作は別ノードに書くこと。
2. `go` は `if` **より先に**処理される。
   同一ノードに `go` と `if` を書くと `go` のジャンプが `if` に上書きされうるため、混在は禁止。
3. `still` / `card` / `wait` / `ch` / `end` は途中で `return` するため、
   それ以降のキー（`chap` など）は評価されない。
4. `chapTitle` は `card` より前に評価されるので同居可能だが、実装では別ノードに分けられている。

## 4. 選択肢（`ch`）

```js
{ch:[
  {t:'表示テキスト', tag:'傾聴', line:'実際に画面へ出す発話',
   silent:1, req:{...}, hide:{...},
   eff:{'LEN.trust':8}, set:{FLAG:1}, inc:{CNT:1}, memo:['題','本文'],
   cost:3, timeout:1, go:'ラベル'}
], sec:9}
```

| キー | 意味 |
|---|---|
| `t` | ボタンに出る文言 |
| `tag` | 左肩の札（`傾聴` `確認` `指摘` `沈黙` `受容` `約束` `切電` `教える` `連携` など）|
| `line` | 選択後にログへ出す実際の発話。省略時は `t` がそのまま出る |
| `say:false` | 選択後にログへ何も出さない（内心の選択）|
| `silent` | 斜体表示（沈黙の選択肢）|
| `req` | 条件式。**不成立でもボタンは出るがロック**され「— まだ言葉が見つからない」と表示 |
| `hide` | 条件式。**不成立ならボタン自体が出ない**（周回限定の隠し選択肢）。表示時は紫枠 |
| `eff` | `'キャラID.パラメータ': 増減値` の辞書 |
| `set` / `inc` | フラグ代入／加算 |
| `memo` | 相談メモへ追加（トーストは出ない）|
| `cost` | 消費時間（分）。**既定 2 分** |
| `timeout` | 制限時間切れ時に自動選択される選択肢の印 |
| `go` | 遷移先ラベル。省略時はノード列を素通しで次へ |

**`sec`（制限時間・秒）** を書くと赤いバーが減り、切れると
`timeout:1` の選択肢が、無ければ**表示リストの最後の選択肢**が自動選択される。
自動選択時はログに「（沈黙した）」と出る。

`sec` の置き場所は 2 通りある。シナリオは一貫して後者を使っている。

```js
{ch:[...], sec:15}          // 選択肢ノードに直接書く
{sec:15}, {ch:[...]}        // 直前に独立したノードとして置く（本作の書き方・全10箇所）
```

エンジンは `{sec:n}` 単独ノードを見つけると値を預かり、**次に現れた選択肢ノードに適用**して
預かりを解除する。章を切り替えると預かりは破棄される。
この預かり方式が成立するのは「`{sec:n}` の直後が必ず選択肢ノードである」ことが
前提なので、`tools/check.mjs` と `tools/regression.mjs` がその配置を検査している。

> `req` と `hide` の違いが本作の周回設計の要。
> `hide` は「その周回では選択肢の存在自体を知り得ない」、
> `req` は「選択肢は見えるが条件を満たしていない」を表す。

## 5. 条件式 DSL

`cond(c)` が評価する。`c` が falsy なら常に `true`。

| キー | 形 | 意味 |
|---|---|---|
| `and` | 条件式[] | 全成立 |
| `or` | 条件式[] | いずれか成立 |
| `f` | フラグ名 | フラグが真 |
| `nf` | フラグ名 | フラグが偽 |
| `cnt` | `[フラグ名, n]` | カウンタが n 以上 ※**シナリオ未使用** |
| `tr` | `[キャラID, n]` | 信頼度が n 以上 |
| `dbt` | `[キャラID, n]` | 疑念が n 以上 ※**シナリオ未使用** |
| `alive` | キャラID | 生死が `生存` |
| `loop` | n | 周回数が n 以上 |
| `recs` | n | **周回跨ぎ**。裏を暴いた録音の累計（`G.recs`）が n 件以上 |
| `cleared` | END名 | **周回跨ぎ**。そのエンディングに到達済み（`G.endings`）|

判定は **上から最初に一致したキーだけ** を見て返す（複数キー併記は先勝ち）。
どのキーも無ければ `true`。

## 6. 状態

### 6-1. `S` ― 周回内の状態（セーブ対象・`ml:save`）

| フィールド | 内容 |
|---|---|
| `loop` | 現在の周回数（1始まり）|
| `day` / `clock` | 日付（1〜14）と時刻（分単位の整数、22:00 = 1320）|
| `chapter` / `chapTitle` | 現在の章IDと章名 |
| `flags` | フラグ辞書。値は 1 か整数カウンタ |
| `chars` | `TRACKED` 6名のパラメータ（§7）|
| `noise` | 現在のノイズレベル 0〜3 |
| `memo` / `evd` / `tl` / `rel` / `vm` / `hist` / `recs` / `stills` | 各資料パネルの内容 |
| `cur` / `callStart` | 通話中の相手と、通話開始時刻（履歴の通話時間算出用）|

### 6-2. `G` ― 周回を跨ぐ状態（セーブ対象・`ml:global`）

| フィールド | 内容 |
|---|---|
| `loops` | 到達したエンディングの累計回数（＝完了周回数）|
| `endings` | 到達済みEND名の配列 |
| `recs` | **裏内容を暴いた録音IDの配列**（SECRET条件・周回引き継ぎ）|
| `stills` | 解放済みスチルIDの配列 |
| `memo` / `evd` / `rel` / `tl` | 次周回へ引き継がれる資料 |

**周回引き継ぎの規則**（`startGame(carry=true)`）

- 引き継ぐ: 録音の「暴かれた」状態・相談メモ・証拠・相関図・事件年表・スチル
- 引き継がない: **信頼／疑念／恐怖／ストレス／生死／その他すべてのフラグ**
- 引き継ぎ時に `LOOP_02 = 周回数` がセットされる

> 「パラメータはリセットする＝もう一度ちゃんと話を聞き直させる」が
> 設計意図（design.md §12）であり、実装もそれに従っている。

### 6-3. 永続化

`window.storage.set/get`（非標準API）を使い、失敗時はモジュール内変数 `mem` に退避する。
`mem` はページリロードで消えるため、素のブラウザでは実質セーブが効かない（GAP参照）。

## 7. パラメータ

`TRACKED = ['LEN','HYU','JIN','MUN','GER','NEO']` の6名のみ追跡・右ペインに表示。
`KAI`（灰堂）`MRI`（室井）`CAN`（カナタ）`UNK` `ME` は表示専用で状態を持たない。

| パラメータ | 初期値 | 範囲 |
|---|---:|---|
| `trust` 信頼 | 20 | 0〜100（クランプ）|
| `doubt` 疑念 | 0 | 0〜100 |
| `fear` 恐怖 | 0 | 0〜100 |
| `stress` ストレス | 0 | 0〜100 |
| `life` 生死 | `生存` | `生存` / `危篤` / `死亡` / `消失` |
| `state` 精神状態 | `安定` | 下式で自動導出 |

**精神状態の導出（`applyPar` 内）**

```
life !== '生存'          → state = life        （生死が精神状態表示を上書きする）
fear > 75 || stress > 85 → 危機
fear > 50 || stress > 60 → 混乱
fear > 25 || stress > 35 → 動揺
それ以外                  → 安定
```

`life` は `生存` 以外になると `applyPar` 経由で `state` に転写されるため、
右ペインには「消失」「死亡」がそのまま状態として出る。

## 8. フラグ体系

命名は概ね `[対象]_[種別]_[連番]`。値は基本 `1`、`MUN_CUT_XX` のみカウンタ。

### 8-1. エンディング判定に直接使うフラグ

| フラグ | 立つ場所 | 意味 |
|---|---|---|
| `KAI_EXPOSE_01` | ch5 灰堂特定 | 黒幕の特定（GOOD分岐の前提）|
| `GER_KNIFE_01` | ch5 ゲル説得（信頼50以上 or `EVD_TAPE_01` 提示）| ゲルの復讐阻止＝死亡回避 |
| `JIN_RUSH_01` | ch5 ジンパチ説得（信頼55以上 or `JIN_CALL_MISS` 等）| 単独突入阻止＝死亡回避 |
| `NEO_HYU_01` | fin 冒頭の連携依頼 | ネオ＆ヒュウ共闘＝両者の消滅回避 |
| `STORY_TRUE_KEY` | ch5 レニィ想起 / fin ムニ脱出 | 真相解放 |
| `MUN_TEACH_01` | ch1 Day4「煙は這って逃げる」 | 避難刷り込み① |
| `MUN_TEACH_02` | **fin（`hide` により2周目以降＋`EVD_TAPE_01` 必須）** | 避難刷り込み②（物置の鍵）|
| `MUN_TEACH_03` | ch3 / fin「私の声を思い出して」 | 避難刷り込み③ |
| `MUN_CUT_XX` | ムニ回線の切電・見送りごとに +1 | **2以上でTRUE恒久封鎖** |
| `EVD_TAPE_01` | ch5 棚の室井テープ発見 | 冤罪証明の鍵 |
| `EVD_WAVE_01` | ch2 波形照合成功 | 事件連関の証明 |
| `SEC_CALL_01` | pro（2周目以降の隠し選択肢）隠し番号へ発信 | SECRET開始 |
| `MUN_SAVED` | fin ムニ自力脱出 | 歴史改変の成立 |
| `RIFT_CLOSED` | fin 裂け目閉鎖成功 | — |

### 8-2. 終章の到達に効くフラグ

`FIN_LOW`（煙）/ `FIN_KEY`（鍵）/ `FIN_VOICE`（声）の 3 つが揃うと `fin_escape` へ分岐し、
`MUN_SAVED` と `STORY_TRUE_KEY` が立つ。それぞれ `MUN_TEACH_01/02/03` を前提条件（`req`）とする。
`FIN_RUN`（兄が外にいる）と `FIN_ALLY`（跡地から呼びかけ）は演出用で判定には影響しない。

### 8-3. 録音の隠し内容フラグ

`rec` ノードの `flag` は、**0.5倍速または逆再生で聴いたとき**に立つ。

| 録音ID | 題名 | 立つフラグ | 裏に入っているもの |
|---|---|---|---|
| `r01` | レニィ／初回相談 | `EVD_SONG_01` | 雨音の下の子どもの鼻歌 |
| `r02` | ムニ／3:33の通話 | `EVD_KAI_STEP` | 祭囃子・男の声・引きずる足音 |
| `r03` | 無言着信／4件分 | `EVD_HZ_01` | 14Hz 前後の低周波 |
| `r04` | カナタのレコーダー | `EVD_KAI_STEP2` | 跛行の足音（照合対象）|
| `r05` | ヒュウ／最後の通話 | `NEO_VOICE_01` | 混線したネオの声 |
| `r06` | ネオ／混線通話 | `SEC_HINT_01` | 主人公への既視感 |
| `r07` | 室井のテープ | `SEC_HINT_02` | 「七人目の子は、どこへ消えたんだ」|

計 7 件。暴いた録音IDは `G.recs` に蓄積され、**周回を跨いで引き継がれる**。
SECRET はこの `G.recs` が 7 件（＝全部の裏を聴いた）であることを要求する。

個々のフラグのうち分岐に使われるのは `EVD_KAI_STEP` / `EVD_KAI_STEP2`
（第五章の灰堂特定 `req` の `or` 条件）のみで、他は資料表示に使われる。

フラグは周回ごとにリセットされるため、**聴き直すたびに立て直される**
（`playRec` は `opened` の有無にかかわらずフラグをセットする）。
`opened` は「はじめて底が見えた」演出の出し分けにだけ使う。

## 9. エンディング判定 `judge()`

`{end:'check'}` ノード（`ep_normal` と `ep_true_end` の2箇所）から呼ばれる。

条件は design.md §6（エンディング表）と §12（TRUE / SECRET 解放条件）に対応する。
両者が食い違う場合は、より具体的な §12 の条件リストを採る。

```js
MAIN      = ['LEN','JIN','GER','HYU','NEO']    // 「現在組」。ムニは十年前の人物なので含まない
alive(k)  = S.chars[k].life === '生存'
allAlive  = MAIN.every(alive)
mainAlive = MAIN.filter(alive).length

goodBase  = KAI_EXPOSE_01 && GER_KNIFE_01 && JIN_RUSH_01 && alive('LEN')

trueCond  = goodBase && allAlive
         && MUN_TEACH_01 && MUN_TEACH_02 && MUN_TEACH_03
         && MUN_CUT_XX < 2
         && EVD_TAPE_01 && EVD_WAVE_01 && NEO_HYU_01 && STORY_TRUE_KEY

secretCond= trueCond && SEC_CALL_01
         && G.recs.length >= 7 && G.endings に 'TRUE' を含む
```

判定は **上から順に最初に成立したものを返す**。

| 順 | END | 条件 | design 対応 |
|---:|---|---|---|
| 1 | `SECRET` | `secretCond` | §12「TRUEクリア後…隠し番号へ発信＋EVD_REC_S1〜S7全回収」|
| 2 | `TRUE` | `trueCond` | §12 の①〜⑥ |
| 3 | `GOOD` | `goodBase && allAlive` | §6「灰堂逮捕＋剛三冤罪証明＋現在組全員生存」|
| 4 | `BAD` | `mainAlive <= 2` **または** `!RIFT_CLOSED` | §6「主要生存者2名以下／裂け目閉鎖失敗」|
| 5 | `NORMAL` | 上記いずれにも当てはまらない | §6「現在の事件は阻止／ムニ死亡／灰堂の全容未解明」|

> BAD の「／」は **or** として実装している。BAD の文面が「澪原市は地図から消えた」＝
> 裂け目が開いたままの結末を描いているため、裂け目未閉鎖は生存者数と独立に BAD とみなす。
> 裏を返すと **NORMAL には `RIFT_CLOSED` が必須**で、これは NORMAL の
> 「現在の事件は阻止」という記述と整合する。

### 9-1. 終章側のゲート（`judge()` の手前）

`fin_after` で先にこの条件を見て、通れば `ep_true` 経路、通らなければ `ep_normal` 経路になる。

```
MUN_SAVED && RIFT_CLOSED && KAI_EXPOSE_01 && GER_KNIFE_01 && JIN_RUSH_01
```

- 通らない → `ep_normal` → `{end:'check'}` → judge は最大でも **GOOD** を返す
  （`MUN_SAVED` 無しでは `STORY_TRUE_KEY` が立たないため `trueCond` は成立しない）
- 通る → `ep_true` → 15歳のムニからの着信 → `SEC_CALL_01` があれば `ep_secret`、
  無ければ `ep_true_end` → `{end:'check'}`

### 9-2. SECRET はシナリオ側のゲートで分岐する

終章 `ep_true2` の末尾に次の分岐があり、ここを通ったときだけ
`ep_secret`（`{end:'SECRET'}` を直接実行する）へ入る。

```js
{if:{and:[{f:'SEC_CALL_01'},{recs:7},{cleared:'TRUE'}]}, then:'ep_secret', els:'ep_true_end'}
```

`judge()` 側の SECRET 条件はこれと同じ内容で、`{end:'check'}` 経由で来た場合の
保険として残してある。通常はシナリオ側のゲートが先に効くため、
`judge()` の SECRET 分岐が使われることはない。

### 9-3. 到達に必要な最小周回数

| END | 最小周回 | 理由 |
|---|---:|---|
| BAD / NORMAL / GOOD | 1 | 1周目で到達可能 |
| TRUE | **2** | `MUN_TEACH_02` の選択肢が `hide:{and:[{loop:2},{f:'EVD_TAPE_01'}]}` |
| SECRET | **3** | `cleared:'TRUE'` を要求するため、TRUE を取った周回の次が最短 |

`EVD_TAPE_01` は周回引き継ぎ対象**ではない**（フラグはリセットされる）ため、
TRUE 周回でも第五章でテープを再取得する必要がある。

## 10. エンディング後の処理 `endGame()`

1. `G.endings` に END 名を追加（重複なし）
2. `S.memo` / `evd` / `rel` / `tl` を `G` へコピー（＝次周回への引き継ぎ確定）
3. `G.loops` を +1
4. セーブしてエンディング画面を表示（「次の周回へ」／「タイトルへ」）

## 11. 実装上の落とし穴（シナリオ執筆時の注意）

1. **フラグ操作を表示ノードに同居させない。** `say`/`nar`/`sys` は即 `return` するため
   同じノードの `set` は無視される。
2. **`go` と `if` を同居させない。** `go` が先に評価される。
3. **`day` は時刻を 22:00 に巻き戻す。** `day` の後に `clock` を書く順序を守ること。
4. **`nar` では時刻が進まない。** 時間経過を見せたいときは `clock` を明示する。
5. **`tlfix` は年表の index 1 を固定で上書きする。** 空白行の位置を動かすと壊れる。
6. **`meet` の `known` は上書き**、`know` は追記。初遭遇時のみ `meet` を使うこと。
7. **`hide` が不成立の選択肢は `sec` のタイムアウト既定値に影響する。**
   タイムアウト時は「表示されている選択肢の最後」が選ばれるため、
   時間制限のあるノードでは `timeout:1` を明示すること。
8. **ラベルは章をまたげない。** `go` は同一章配列内のみ。章移動は `chap` を使う。
